## 1. 秋山2013(移動様態適応PF)

**書誌**: 秋山高行, 中原豪, 山崎勝也, 大橋洋輝, 佐藤暁子: 移動様態に応じたパーティクルフィルタによる
歩行者自律測位方式の提案と評価, FIT2013(第12回情報科学技術フォーラム), RO-017, 第4分冊, pp.165–171, 2013.
(PDFのファイル名は「自立」だが、題名は「自律」)

**何をしたか**
- 目的は、スマートフォンでの**計算負荷の削減**(精度を落とさずに粒子数を減らす)。p.165
- 方位の推定誤差が位置に与える影響は、直進時と屈折時で違う → 様態に応じてサンプリング範囲(ノイズ)を変える。p.166
- 磁気は使わない(鉄製物体で乱れるため)。加速度とジャイロのみ。p.166
- 状態は(x, y, θ, 移動様態)。歩行速度 = pace×Pitch_t ± 0.1(pace=0.4、Pitch_t=1秒あたりの歩数)。p.166、式(2)(3)
- 様態判定: 滞留か歩行かは歩数検知で判定。直進か屈折かは「**8秒間で方位が30度以上変化したら屈折**」。p.166
- 歩行距離と方位に、様態ごとに分散の違うガウス雑音を加える(直進は小さく、屈折は大きく)。滞留時はセンサー値を位置推定に使わない。p.167、式(4)(5)
- **粒子数は直進10、屈折20**。p.167
- 重み: 前回の位置から更新後の位置への線分が**壁と交差したら0、しなければ1**。p.167、式(9)
- PFの更新間隔は**8秒**(短いと壁の効果が出ず、長いと表示の更新が遅い)。p.167
- 20m間隔のリセットポイント(環境に設置する機器)で位置と方向を補正する実験もしている。p.169

**実験と主な数値**
- 鉄道博物館(幅5m程度の通路が主)、Nexus S を手に持って固定、加速度50Hz・ジャイロ100Hz。地図はCAD図面と現地の実測から作成。p.167
- 評価指標は、正解軌跡(**人手で記録**)との各時刻の誤差の平均と、計算時間。p.167
- 約40mの単純な経路4通り(表2): 平均誤差は、PFなしが4.6〜5.8m、PFが2.3〜3.3m、提案方式が2.4〜3.1m。p.169
- 自由な見学行動を模した歩行(表4): 提案方式が**PFより悪くなる経路があった**(経路1で平均12m、PFは3.6m)。原因は、滞留と細かい転回が繰り返されて様態判定に失敗したこと。p.168–169
- リセットありの場合(表6・7): 平均誤差は、PFが3.3m、提案方式が5.2m。計算時間は、PFが6.0秒、提案方式が3.2秒。著者は「精度を保ったまま計算時間を約1/2」と述べている。p.169–170
- 256秒の測位を3.25秒で計算。Android端末(Galaxy S3)でも実時間で動作。p.170–171
- 著者が挙げた課題: 10m以上開けた空間では壁が使えない。自由な行動での様態判定。リセットの誤差。端末の持ち方への依存。p.171

**本研究が取り入れた点**: 3様態の区分と、様態ごとに粒子数・ノイズを変える考え方。予測→重み→リサンプリングの枠組み。
壁を横切った粒子の重みを0にする処理(`pdr_pf_improved.py`の`update()`内の`weights[hit_wall] = 0.0`)。

**本研究との違い**
- 目的: 秋山は計算量の削減。本研究は、複雑な廊下での精度と頑健性(全滅回数など)。
- 屈折判定: 1.5秒の窓で「方位変化20度以上 **かつ** ヨーレート(75パーセンタイル)20度/秒以上」。直進への戻りにヒステリシスあり(`detect_move_behavior`)。
- 粒子数: 250/600/100(比率を保って拡大)。さらに、不確実性適応でNeff比率に応じて増減する。
- 更新: 8秒ごとではなく1歩ごと。
- 壁: 0/1の判定に**加えて**、壁までの距離による連続的な重みを掛ける(式と実際の効き方は[comparison_methods.md](comparison_methods.md))。さらに経路帯(自動抽出)を使う。
- 外部機器によるリセットは使わない(IMUと地図のみ)。

**引用するときの注意**
- 「精度を保ったまま」は著者の主張。表6では平均誤差が3.3→5.2mに増えているので、そのまま書き写さない。
- (2026-10-01)自由歩行で様態判定に失敗した原因は、著者の**推測**(p.169「〜と思われる」)。「報告している」と書かない。
  滞留時にセンサ値を使わない理由(「位置がほとんど変わらないから」など)は原文に**無い**。p.167の事実だけを書く。
  「幅5m程度の通路」は「主に構成されている」(p.171)。今後の課題はほかにリセット誤差・端末の持ち方もある(p.171)。
  直進時は歩行距離の誤差の占める割合が屈折時より大きい、とも述べている(p.166)。
- 秋山の課題(開けた空間、様態判定の失敗)は、本研究の経路帯抽出と屈折判定の改良の動機として書ける。
- 本文で、粒子数を適応的に変える既存手法として Heinemann ら(IROS 2006)と KLDサンプリング(Kwok ら、ICRA 2003)を挙げている。
  本研究の不確実性適応粒子数は、この系統の考え方に近い。**「本研究独自」と書くのは「様態別の粒子数にNeff比率による増減を重ねた組み合わせ」の範囲にとどめる**。
  KLDサンプリングの原文(Fox2003)は2026-09-30に確認し、卒論[13]として引用済み(下の「2.6節用の文献」)。
  Heinemann ら(推定精度に応じて粒子数を変える方法)は**未読**で、卒論では名前を出さず文献にも挙げていない。
- `pdr_pf_improved.py`冒頭付近のコメント(「原論文の0/1二値重みではなく…連続的な尤度重み付けに拡張」)は、0/1の処理が残っている実装と合わない。卒論では「0/1に加えて連続的な重み」と書く。

**確認状況**: 本文と表は読めた(表2〜5は2段組みが崩れていて、最大誤差の対応が曖昧)。式(1)〜(9)は画像から確認した。
ただし、式(3)の「0.1」の前の符号は画像が粗くて判別できない(「−」に見える)。図(軌跡など)は未確認。

## 2. 古屋2023(地図データでPDRの誤差を補正)

**書誌**: 古屋響生, 屋代智之: 地図データを誤差補正に用いたPDRによる屋内位置推定手法の提案,
情報処理学会研究報告, Vol.2023-MBL-109 No.15 / Vol.2023-ITS-95 No.15, 2023.(千葉工業大学)

**何をしたか**
- PDR: 加速度にローパスフィルタ(式(1))をかけ、**10m/s²のしきい値**を超えて局所最大になったら1歩。p.2–3
- 歩幅は**身長×0.46の固定値**(上坂ら2011に基づく)。方位はZ軸まわりの角速度の積分。磁気は使わない。p.3
- 地図補正(3.5節): 格子状の占有地図(歩行可能0/不可1)を使う。PDRの軌跡が歩行不可の場所にぶつかったら、次の2つの角度で場合分けして補正する。p.3–4
  - θA: 衝突した軌跡と壁の角度。しきい値30°
  - θB: 衝突前5歩分の回転角の合計。しきい値45°(以下なら直進中、超えたら方向転換中と判定)
  - (1) θA≦30°(横の壁へ徐々に近づいた = 方位誤差) → 5歩前の方位をθAだけ歩行可能な側へ直す
  - (2) θA>30°かつθB>45°(曲がった後に手前の壁 = 歩幅が短い) → さかのぼって10歩分の歩幅を5%大きくし、ぶつからなくなるまで繰り返す。直した歩幅を以降も使う
  - (3) θA>30°かつθB≦45°(曲がる前に奥の壁 = 歩幅が長い) → 同様に5%小さくする
- **地図補正は実装していない**。「実装までは行えなかった」ため、補正後の結果は想定図(図11)だけ。p.3、p.5

**実験と主な数値**(PDRのみの結果)
- 千葉工業大学津田沼キャンパス7号館5階の廊下、1周72mのループ。iPhone 11(MATLAB Mobile、100Hz)。身長170cmの被験者1名。1周を3回、2周を3回。p.4
- 歩数の誤差は全6回で2歩以内。p.4
- 1周(72m): 推定距離75.1〜75.9m(誤差3.1〜3.9m)、回転角の誤差−12.6〜−14.2°。p.5 表1
- 2周(144m): 距離誤差3.0〜5.4m、回転角の誤差−22.9〜−31.5°。p.5 表2

**本研究との違い**
- 目的は同じ(地図でPDRの蓄積誤差を減らす)。方法は、古屋が決まった規則で1本の軌跡を直すのに対し、本研究は確率的(PF)。
- 本研究は実装して評価まで行っている。古屋は補正の提案と想定図まで。
- 歩幅: 古屋は身長からの固定値。本研究はSmartPDRの式(加速度の振幅から1歩ごとに推定)に、共通の校正ゲインを掛ける。
- **古屋にあって本研究に無いもの**: 壁へのぶつかり方から**歩幅そのものを直す**考え方。本研究のPFは1歩ごとの歩幅のばらつきを持たせるだけで、
  歩幅の偏りを学習しない(ゲインは事前に共通の値を求める。[step_length_calibration.md](step_length_calibration.md))。考察・今後の課題の材料。

**引用するときの注意**: 5章とまとめでは、補正が「可能」「分かった」と書かれているが、根拠は想定図である。
「地図補正の効果を示した研究」として引用しない。「提案のみで、実装・評価は今後」と書く。

**確認状況**: 文字化けを直し、読む順に並べ直して本文を確認した。英数字(PDR、θA、30°など)は前後の行にずれて出るため、
条件の組み合わせ(上記(1)〜(3))は文脈から組み立てた。卒論に数値を書くときは、p.3–4を原文で見直すこと。図は未確認。

## 3. Kang2015(SmartPDR)

**書誌**: W. Kang and Y. Han: SmartPDR: Smartphone-Based Pedestrian Dead Reckoning for Indoor Localization,
IEEE Sensors Journal, vol.15, no.5, pp.2906–2916, May 2015.(KAIST)

**何をしたか**
- インフラも事前のデータベースも**地図も使わない**PDRが主張。地図は常に手に入るとは限らない、という立場。p.2906–2907
- ステップ検出: 端末座標を地面座標へ変換し、HPFで重力を除き、移動平均(LPF)で平滑化。そのうえで、次の3条件がそろった時刻を1歩とする。p.2909、式(3)〜(8)
  - ピーク > 0.5m/s²
  - 前後の谷との差 > 1.0m/s²
  - 前側が増加、後ろ側が減少
- 方位: 磁気とジャイロの両方を使う。2つの相関と磁気の変化量で、4つの場合に分けて使う情報源を選ぶ(重み 前回:磁気:ジャイロ = 2:1:2、しきい値5°と2°)。1歩の方位は、歩の間で加速度が谷になる時刻の値を使う。p.2910–2911
- 歩幅: 垂直方向の加速度の山と谷の差から推定する(Weinberg 2002)。4乗根式と対数式を、3.230m/s²を境に切り替える(式(28)、β・γの値もp.2912)。p.2911–2912

**実験と主な数値**
- Galaxy Note / Note II、20Hz、手に持って前方に構える。KAISTの建物で8の字の経路168.55m(約215歩、約2分)。5人で50回。p.2912–2913
- 方位誤差は平均2.28°(標準偏差3.63°)。p.2913–2914
- 位置誤差は平均1.35m、最大1.62m(全区間で2m未満)。p.2914–2915
- 課題: 端末の機種による違い、階の認識、建物入口の位置は既知と仮定。p.2915

**本研究が取り入れた点**: ステップ検出(`detect_steps_smartpdr`)と歩幅推定(4乗根式と対数式の切り替え)。コードでは`[SmartPDR]`タグ。

**本研究との違い**
- 方位は取り入れていない: ジャイロ(Madgwick、updateIMU)かAndroidの回転ベクトル(`yaw_deg`)を使う。記録に磁気の列が無い。
- 2026-09-02に2点変えた([step_length_calibration.md](step_length_calibration.md))。
  - 原論文の条件のままだと、歩行の第2高調波に反応して歩数が1.7〜1.8倍に過検出された → 歩調の上限から最短ピーク間隔を決めた
  - 歩幅が約1/2に過小推定された → 校正ゲインを掛けた
- 立場が逆: SmartPDRは地図を使わないことを主張しており、本研究は地図を積極的に使う。関連研究では、この対比で位置づけられる。

**引用するときの注意**: SmartPDRの係数(β、γ、しきい値)は、原論文の端末と20Hzで決めたもの。本研究のデータでは、そのままでは合わなかった
(上記の過検出と過小推定)。「SmartPDRの方式をそのまま使った」とは書かない。

**確認状況**: 本文(英語)は全文読めた。方位の融合の式(17)〜(19)は崩れていたが、重みとしきい値は本文にある。図は未確認。

## 4. 上田2005(PFの致命的な推定誤りからの回復法)

**書誌**: 上田隆一, 新井民夫, 浅沼和範, 梅田和昇, 大隅久: パーティクルフィルタを利用した自己位置推定に生じる
致命的な推定誤りからの回復法, 日本ロボット学会誌, Vol.23, No.4, pp.466–473, 2005.

**何をしたか**
- 移動ロボットのMCL(PFによる自己位置推定)で、真の姿勢の周りに粒子が無くなった状態を「**誘拐状態**」と呼ぶ。
  原因は、人に動かされる(遠い距離)、スリップや衝突(近い距離)など。ベイズの式だけでは戻れないので「リセット」が要る。p.466、p.468 式(6)
- 比べた4方式。p.468–469
  - センサリセット(SR、Lenser ら 2000): 尤度の合計αがしきい値α_thを下回ったら、センサー観測から得た分布を混ぜて粒子を配置し直す
  - 履歴センサリセット(HSR): αの長期平均と短期平均の比で判定し、矛盾が続いたときだけリセットする
  - **膨張リセット(ER、この論文の提案)**: **推定姿勢を変えずに**、粒子の分布を広げる。
    分布の範囲に接する直方体(一辺は標準偏差の6倍、下限300mm・60°)へ粒子をまき直す。連続して起きると範囲が指数的に広がる
  - SR+ER(提案): 分布が広い(σx>300mm、σy>300mm、σθ>60°のどれか)ときはSR、それ以外はER
  - (ERの6倍・下限、SR+ERの切り替え値はp.470の実装の設定)
- RoboCup 4足ロボット(ERS-210)の**シミュレーション**で、5種類の状況で比較した。粒子数は主に1000。p.469–470
  - 位置の追従
  - 初期位置が不明な状態からの推定
  - 誘拐(遠い距離)
  - スリップ(近い距離)
  - センサーの致命的な誤り

**主な結論**
- 誘拐が無い追従にはリセット不要。近い距離の誘拐(スリップ)にはERが有効。SRとERを組み合わせると、どの距離の誘拐にも対応できる。p.473
- リセットを使うと、使わないときより1桁少ない粒子数で同等以上になる場合がある(初期位置が不明な状態から推定するとき)。p.472
- SRは、センサーの雑音で不要なリセットが起き、近い距離の誘拐では分布を広げすぎる。p.467

**本研究との関係**
- 本研究の「全滅」(全粒子の重みが0)は、リセットの判定に使う尤度の合計αが0になった場合にあたる。
  (2026-10-01訂正)「誘拐状態の極端な場合」とは書かない。誘拐状態は粒子の**配置**(真の位置の周りに粒子が無い)で
  決まり、全滅は**重み**で決まるため。方位誤差で真の位置の近くの粒子ごと壁に当たることもある。
- 全滅からの復帰(`update()`内、2026-09-24から「移動前の平均+この歩の移動量」の周りへまき直す)は、**推定位置を保って広げる点でERに近い**。
- 違い
  - 発動条件: 上田はα<α_th(しきい値)で、全滅する前に発動できる。本研究は合計が0のときだけ。
  - 広げ方: 上田は分布の大きさに合わせ、連続すると拡大する。本研究は固定のσ(`recovery_sigma`)。
  - SRは本研究では使えない: 絶対位置を観測する手段が無い(地図の壁だけ)。
- 復帰の中心を進めても効果が小さかったこと、方向を変えて進める案が未検討であることは[comparison_methods.md](comparison_methods.md)の2026-09-24の項。
  ERのように連続全滅で広げる案も未検討(判断待ちではなく、検討していない)。
- 同じ「推定が不確か」という信号に対して、上田は分布を広げ、本研究の不確実性適応は粒子数を増やす。考察で対比できる。

**引用するときの注意**: 対象はロボット(カメラでランドマークを観測)で、評価はシミュレーションのみ。歩行者PDRに当てはめるときは、
「考え方を参考にした」と書き、数値(しきい値など)は流用しない。
